# GODFIN Production Remediation Plan

This working plan covers every stable primary audit ID, all eight validated supplemental IDs, and the two explicit owner requirements. Status is evidence-based and will be updated only after each item meets its acceptance criteria.

## Dependency order

1. Preserve the baseline and build characterization tests for Critical/High findings.
2. Resolve parser and ledger semantics before trusting downstream calculations.
3. Establish exact money, schema, backup, reset, migration, and restore invariants.
4. Harden authentication, local API trust, settings, serialization, exports, and AI privacy.
5. Complete Gmail OAuth/synchronization and live owner setup.
6. Reconcile commerce, signed entitlements, refunds, pricing, Supabase, and public claims.
7. Finish accessibility, provider contracts, durable jobs, performance, packaging, and release evidence.

## Commit and verification policy

- Add characterization tests before parser, money, migration, payment, licensing, reset, or authentication changes.
- Run GitNexus upstream impact analysis before editing every function/class/method and stop for any High/Critical blast radius warning.
- Run targeted tests after each coherent change, then the full backend, frontend, website, Playwright, package privacy, audit, and platform-appropriate build gates.
- Run `gitnexus detect-changes --repo GODFIN` before every commit.
- Keep commits small and reference the affected finding IDs.
- Never mark unsupported native execution, live provider behavior, signing, legal review, or public launch as passed without direct evidence.
